# tap_topics.txt -- PURPOSE: the ONE list of what the "ROS tap" copies from the team stack on the Jetson (inside the
# container astra-hil) to the simulator PC, one way, read-only (docs/jetson/HIL_DESIGN.md section 7). The PC's score
# report (score_run) and live phase view (phase_monitor) are ROS programs that must stay on the PC, so they need these
# topics; nothing is ever sent back into the Jetson's ROS graph. To copy one more topic, add one line here.
#
# Format: one "topic type" pair per line ("#" starts a comment). Sections:
#   [common]  MAVROS state, position and status texts: needed with every camera pipeline
#   [new]     the team's NEW video pipeline (zr10_ros2 + zr10_stream + the yolo26 detector; the field default)
#   [legacy]  last year's photo pipeline (video_cam "siyi" + new_od): kept as the labelled "legacy (2025)" option
#   [nodes]   the team node names whose presence the PC mirrors as empty nodes /jetson/<name> (one per line), so
#             phase_monitor's "main_controller is NOT RUNNING" warning keeps working through the tap
# The container's entrypoint passes the parts of the pipeline that runs (ros_tap.py send --parts common,new).
# Never add raw or annotated video (/zr10/image_raw, /detection/annotated, /image_raw): ~2.7 MB per frame.
# Each topic's QoS is copied from its publisher, so the PC side matches it the way it does today.
